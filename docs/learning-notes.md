# 项目学习笔记

每次迭代按以下方式学习和复盘：

1. **目标**：这个模块解决哪个真实问题？
2. **原理与取舍**：为什么选择当前实现，而不是更复杂的方案？
3. **代码链路**：请求进入哪个接口，状态如何流转，结果在哪里保存？
4. **验证**：如何证明它真的工作，而不是只写了代码？
5. **面试表达**：用“问题—设计—结果—取舍”讲清实现。

## Web 演示界面

界面由 FastAPI 同源托管，提交请求后真实调用 `POST /research`。它将一个 `ResearchContext` 按报告、计划、证据和 Trace 四个视图展示。这样既能验证 API 返回结构，也能在演示时呈现 Agent 的可追溯执行过程。

选择原生 HTML、CSS、JavaScript 的原因是：当前页面交互有限、同源部署简单，并能将注意力放在 Agent 工程本身。需要复杂协作、局部实时刷新或组件复用时，再迁移至 React。
